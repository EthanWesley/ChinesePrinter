# 分段循环输入与暂停/继续

网页保留开始时的文本快照，第一段为 32 个 UTF-16 单元，之后每段
128 个单元；分段边界不拆开有效代理对。只编码并发送当前段，确认
设备完成后再处理下一段。Worker 每次收到一小段，不再复制整篇文本。

Base64 模式保留最多两个 UTF-8 字节作为下一段的前缀，只在最后一段
补齐 Base64 填充，保证分段输出与整段编码完全一致。

暂停在网页端阻止后续分段，同时通过 `/api/pause` 暂停当前设备任务。
`/api/resume` 继续当前位置。停止立即取消待编码分段并阻止后续发送，
在当前请求被接受后通知设备停止，确认任务结束后才允许再次开始。
输入框内容始终保留。请求或状态异常时停止发送后续分段并提示错误。

Shell 在每个字符前检查暂停/停止标志。C 原生写入器在完整 Alt 码字符
完成、所有按键释放后检查控制标志，避免中途杀进程留下 Alt 按住。
C 记录实际完成项数，暂停及停止时不再把整段标记为完成。ARM 静态
二进制随代码一起更新，安装流程继续复制该二进制。

检查包括全部编码分段一致性、首段大小、停止后的剩余文本不发送、
真实 Shell HTTP 控制、原生 C 报告序列与暂停/继续/停止。C 行为检查
在普通文件上模拟 HID；实际 USB 传输和目标电脑效果仍需设备验收。
产物保留在 `.deleted/2026-10-07/`。

检查命令：`node tests/encoding.test.cjs`。
原生检查需先用本机 gcc 编译，再运行
`python3 tests/native_controls.py <本机 hid_writer 路径>`。
